## Em uma frase

Um LLM (*large language model*, modelo de linguagem grande) é um modelo de IA treinado para reconhecer padrões em grandes volumes de linguagem e prever quais tokens são mais prováveis em determinado contexto — a base para capacidades como escrever, resumir, traduzir e responder perguntas.

## Tokens, não palavras

Um LLM não recebe texto do jeito que nós lemos. Antes de ser processado, o conteúdo é dividido em unidades menores chamadas *tokens* — um token pode ser uma palavra inteira, parte de uma palavra, pontuação, ou outro fragmento de texto (ver [`google-ml-crash-course-intro-llm`](../../references/sources.yaml)). O modelo aprende relações estatísticas entre tokens e estima a probabilidade de um token, ou sequência de tokens, aparecer em determinado contexto.

Quando um LLM gera uma resposta, ele produz tokens sucessivamente, um a um, com base no contexto disponível e nos padrões aprendidos durante o treinamento.

## Por que Transformers importam

A maioria dos LLMs modernos é construída sobre a arquitetura *Transformer*, apresentada em 2017 no artigo "Attention Is All You Need" (ver [`attention-is-all-you-need`](../../references/sources.yaml)). Uma ideia central dos Transformers é o mecanismo de *attention*, que permite ao modelo relacionar diferentes partes de uma sequência entre si ao processar informação — isso viabilizou treinar modelos maiores e trabalhar com contextos muito mais amplos do que arquiteturas anteriores.

Não é preciso entender a matemática por trás de Transformers para usar um LLM, mas vale entender o essencial: o modelo não consulta frases prontas em uma base de respostas. Ele calcula uma saída nova a cada vez, a partir do contexto recebido e dos padrões representados em seus parâmetros.

## Pré-treinamento

A primeira grande etapa costuma ser o *pre-training*: o modelo é exposto a grandes volumes de dados e aprende padrões de linguagem, relações entre conceitos e regularidades presentes nesses dados, ajustando seus parâmetros para melhorar suas próprias previsões. Dependendo da arquitetura, o objetivo pode ser prever o próximo token ou reconstruir tokens ausentes — o ponto central é o mesmo: aprendizado por ajuste de parâmetros, não memorização literal.

Vale evitar dizer que o modelo "armazena" ou "comprime todo o conhecimento da internet". Seus parâmetros representam padrões aprendidos durante o treinamento — isso não funciona como um banco de dados do qual fatos são recuperados exatamente quando necessário.

## Pós-treinamento

Um modelo pré-treinado não é automaticamente um bom assistente. Depois do pre-training, modelos passam por diferentes formas de *post-training* para melhorar capacidades como seguir instruções, produzir respostas mais úteis, e se comportar de acordo com certos objetivos ou princípios — mas os caminhos para chegar lá variam entre laboratórios.

Um exemplo conhecido é o InstructGPT: a OpenAI usou demonstrações humanas, *supervised fine-tuning* e depois *reinforcement learning from human feedback* (RLHF) para aproximar o comportamento do modelo das preferências dos usuários (ver [`ouyang-2022-instructgpt`](../../references/sources.yaml)). Outros laboratórios seguem caminhos diferentes: a Anthropic desenvolveu Constitutional AI, combinando fine-tuning supervisionado e reinforcement learning orientado por um conjunto explícito de princípios, em vez de depender só de feedback humano direto (ver [`anthropic-constitutional-ai`](../../references/sources.yaml)).

Por isso, "post-training" é um termo melhor do que tratar RLHF como etapa obrigatória de todo LLM — é uma técnica entre várias possíveis, não a definição do processo.

## Inferência

Depois de treinado, o modelo é usado para gerar resultados — esse processo é chamado de *inference*. Ao receber uma entrada, o sistema a transforma em tokens, processa o contexto e calcula possíveis continuações, gerando novos tokens progressivamente até formar a resposta.

Existe uma distinção importante entre **training** (o processo de ajustar os parâmetros do modelo) e **inference** (o processo de usar esses parâmetros já fixos para produzir uma saída). É por isso que conversar com um LLM normalmente não significa que ele está sendo treinado de novo a cada interação.

## O modelo não é o sistema inteiro

Um LLM também não deve ser confundido com o produto que aparece na tela. Um chatbot, agente ou aplicação combina o modelo com outras peças:

```
LLM + instruções + contexto + dados + ferramentas + software
```

O LLM é uma capacidade dentro desse sistema maior — não o sistema inteiro. Isso explica por que dois produtos podem usar exatamente o mesmo modelo e, ainda assim, se comportar de formas muito diferentes.

## Modelos gerais e modelos especializados

Alguns modelos são feitos para funcionar bem numa ampla variedade de tarefas; outros são menores ou adaptados para domínios mais específicos, por caminhos como fine-tuning, distillation ou treinamento direcionado. Especialização pode tornar um modelo menor mais eficiente em determinada tarefa, mas isso não é automático — não significa necessariamente maior precisão ou menor custo em qualquer situação; a escolha depende do problema e precisa ser avaliada na prática.

Da mesma forma, usar dados proprietários não significa necessariamente "treinar um novo LLM". Informações de uma empresa podem entrar como contexto durante a execução, ser recuperadas por outro sistema (veja [`rag`](../systems/rag.mdx)), ou alimentar um processo específico de fine-tuning — são mecanismos diferentes, não a mesma coisa com nomes diferentes.

## O modelo mental mais importante

```
dados de treinamento → padrões aprendidos → contexto atual → previsão de tokens → resposta
```

A resposta pode parecer uma explicação, análise ou raciocínio completo, mas continua sendo produzida por um modelo treinado para gerar sequências a partir de padrões e do contexto disponível. Entender essa diferença ajuda a evitar dois extremos: tratar um LLM como um "autocomplete" trivial, ou imaginar que ele compreende o mundo exatamente como uma pessoa. É um tipo diferente de sistema — com capacidades impressionantes e limitações próprias.

## Equívocos comuns

- "O modelo entende o que está dizendo" — o mecanismo é previsão estatística de tokens, não compreensão no sentido humano.
- "O modelo armazena/comprime todo o conhecimento da internet" — seus parâmetros representam padrões aprendidos, não uma base de fatos recuperáveis com exatidão.
- "RLHF é uma etapa obrigatória de todo LLM" — é uma entre várias técnicas de post-training; outros laboratórios usam abordagens diferentes.
- "Dar dados da empresa ao modelo é treinar uma nova LLM" — normalmente é contexto de execução ou recuperação, não treinamento.

## O que pode dar errado

Modelos podem gerar informação plausível, mas incorreta (frequentemente chamada de "alucinação"), especialmente para fatos específicos, raros, recentes, ou fora do que foi visto no treinamento — o mecanismo de previsão continua o mesmo independentemente da escala do modelo.

## Perguntas para fazer

- Esta tarefa depende de precisão factual garantida, ou de fluência e síntese de linguagem?
- Como eu verificaria se a resposta do modelo está correta antes de agir sobre ela?
- Estou tratando "ter acesso a dados da empresa" como se fosse "a IA aprendeu a empresa"?

## Fontes principais

- Vaswani et al. — "Attention Is All You Need" (2017). Arquitetura Transformer e o mecanismo de attention que sustenta a maioria dos LLMs modernos.
- Google Machine Learning Crash Course — "Introduction to Large Language Models". Fonte institucional para tokens, contexto e treinamento.
- Ouyang et al. — "Training Language Models to Follow Instructions with Human Feedback" (InstructGPT, 2022). Fonte primária para supervised fine-tuning e RLHF como uma das formas de post-training.
- Anthropic — "Constitutional AI: Harmlessness from AI Feedback". Fonte primária para mostrar que post-training não se resume a RLHF — outros laboratórios usam feedback orientado por princípios explícitos.
